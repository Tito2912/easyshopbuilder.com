# Données structurées Shopify (2026)

Les données structurées (schema.org) aident Google à comprendre vos pages et peuvent activer certains enrichissements. Pour l’e-commerce, l’objectif est simple : **Product + Breadcrumb** d’abord, puis le reste.

<h2 id="priorites">1) Priorités (ordre recommandé)</h2>

1. **Product** (pages produit) : prix, disponibilité, avis.
2. **Breadcrumb** : renforce la hiérarchie (home → collection → produit).
3. **Organization / WebSite** : base de crédibilité.
4. **Article** (guides) : pour les contenus éditoriaux.
5. **FAQPage** : seulement si la FAQ est visible et utile.

Évitez le “schema partout” : ça crée des erreurs et n’améliore pas forcément le SEO.

<h2 id="product">2) Schema Product : ce qu’il faut surveiller</h2>

À aligner avec l’UI :

- prix (promo incluse), devise,
- disponibilité (in/out of stock),
- variantes (éviter des incohérences),
- reviews/ratings (uniquement si affichés).

Si vous utilisez des apps d’avis, vérifiez qu’elles n’ajoutent pas un second balisage Product.

<h2 id="breadcrumb">3) Breadcrumb : structure et cohérence</h2>

Le breadcrumb doit refléter une structure logique. Idéalement :

- Home → Collection (catégorie) → Produit

Plus la hiérarchie est stable, plus c’est simple à crawler et à maintenir.

<h2 id="faq">4) FAQ/Article : utile quand c’est contextuel</h2>

FAQ : placez-la sur les pages où elle répond aux questions fréquentes (livraison, retours, compatibilité, entretien). Gardez 3–6 questions maximum, et évitez les FAQ génériques copiées.

Article : utile pour vos guides (SEO, conversion, comparatifs) afin de clarifier le type de contenu.

<h2 id="validation">5) Validation et erreurs fréquentes</h2>

Routine :

- testez vos URLs via l’outil Rich Results,
- surveillez Search Console (Produits, Breadcrumb),
- re‑testez après changement de thème/apps.

Erreurs fréquentes :

- double balisage (theme + app),
- prix/schema non cohérent avec la page,
- disponibilité incorrecte,
- balisage FAQ sur une FAQ invisible.
